# 我的作品发布时间排序设计

## 目标

所有读取“我的作品”的页面统一按作品发布时间从新到旧展示，重复同步、刷新或切换页面不能改变既有顺序。

## 数据设计

- `videos` 表新增可空字段 `publish_time`，保存抖音作品的发布时间。
- 同步作品时，从接口对象的 `create_time`、`createTime` 等兼容字段提取秒级或毫秒级时间戳并标准化为整数毫秒。
- 数据库初始化迁移时，尝试从已有 `raw` JSON 中回填发布时间。
- 无法取得发布时间的历史作品保持可用，不因迁移失败而丢失。

## 排序规则

账号“我的作品”查询统一使用：

1. 有发布时间的作品优先。
2. `publish_time` 从新到旧。
3. 发布时间相同时按数字作品 ID 从大到小稳定排序。
4. 非数字作品 ID 再按作品 ID 字符串倒序兜底。

搜索结果仍保留原搜索排名，不受此改动影响。

## 影响范围

后端 `listVideos({ accountId, isMine: true })` 作为唯一排序入口；“我的作品”、评论管理的作品选择器及其他复用该接口的位置自动获得相同顺序，前端不再分别排序。

## 测试

- 同步返回乱序作品时，查询结果按发布时间从新到旧。
- 再次同步不会因 `updated_at` 改变作品顺序。
- 发布时间相同或缺失时顺序仍确定。
- 搜索结果继续按搜索排名展示。
- 数据库迁移能读取旧数据库并回填可识别的发布时间。
