# GEO 获客知识库设计

## 目标

完善 Vulcan 抖音控制台的知识库模块，并提供一套可直接使用的 GEO 服务获客知识 Demo，支持评论线索私信和私信自动回复生成。知识内容可以后续补齐，但知识库管理、导入、检索和维护能力必须完整。

## 内容结构

在根目录新增 `knowledge-demo/`，每个 Markdown 文件导入后对应一条知识：

1. `01-GEO服务说明.md`：GEO 的通俗定义、适用客户、Demo 服务范围和沟通目标。
2. `02-客户意向识别.md`：高、中、低意向及应忽略场景，提供识别信号与下一步动作。
3. `03-常见问题回复.md`：收费、周期、效果、流程、所需资料、适用行业等问答。
4. `04-获客私信话术.md`：首次触达、需求追问、继续沟通、暂不需要和停止联系等场景。
5. `05-自动回复规则.md`：自动回复语气、长度、知识引用、一次一问和上下文规则。
6. `06-人工接管与禁区.md`：价格未配置、效果承诺、投诉、合同、退款、敏感信息及非文本消息的人工接管条件。

所有文件使用统一头部字段：用途、标签、适用渠道、维护提示。业务事实未知时统一写“根据实际需求评估，由人工确认”，不使用占位价格或虚构案例。

## 运营原则

- 回复自然、简短、专业，不用强推销话术。
- 不承诺搜索排名、曝光量、获客数量或收益。
- 对同一用户避免重复触达；用户拒绝或要求停止时不再营销。
- 明确问题优先直接回答；信息不足时每次只追问一个关键问题。
- 纯表情、图片、视频、语音、投诉、合同、退款和敏感问题转人工处理。
- 本设计只提供内容知识，不改变发送并发、延迟、去重和任务队列。

## 数据与兼容性

保留现有 `knowledge_entries` 作为知识文档表，兼容已经录入的数据。新增分类、来源类型、来源文件名、内容哈希和版本字段，并新增 `knowledge_chunks` 保存文档切分后的检索片段。

- 手动新增和文件导入都生成知识文档及检索片段。
- 文档内容更新后，事务内重新生成片段并递增版本。
- 删除文档时级联删除片段。
- 旧数据首次打开时补齐默认元数据和片段，不丢失原有标题、标签、内容及启用状态。
- 内容哈希用于检测完全重复的导入文件；重复文件默认跳过并显示导入报告。

## 文件导入与导出

- 支持 TXT、Markdown、CSV、JSON，不支持 Word 和 PDF。
- 支持一次选择多个文件，逐个读取并显示成功、跳过、失败数量及每个文件的原因。
- 每个文件保留来源文件名、类型、大小和导入时间。
- CSV 和 JSON 第一版作为可读文本导入，不把未经确认的字段映射成业务事实。
- 支持将全部或选中的知识导出为 JSON 备份，也支持将单条知识导出为 Markdown。

## 知识库页面

知识库页面采用“工具栏 + 文档列表 + 编辑详情”的管理结构：

- 标题、标签、正文和来源文件名关键字搜索。
- 分类、标签、来源类型、全部/启用/停用状态筛选。
- 按更新时间、创建时间、标题排序。
- 分页显示，支持每页 10、20、50 条。
- 列表支持多选、全选当前页、批量启用、批量停用、批量删除和批量导出。
- 详情显示来源、版本、字符数、片段数、创建时间和更新时间，并支持编辑、启停和删除。
- 新增资料与文件导入放在明确的独立操作区，不与浏览编辑区混排。
- 筛选不会覆盖未保存的编辑内容；切换含未保存修改的文档前要求确认。

## 后端接口

- 列表接口支持查询、状态、分类、标签、来源类型、排序和分页参数，并返回总数。
- 新增、更新接口统一校验标题、内容、分类和标签，事务内维护文档与片段。
- 批量接口只接受明确的文档 ID 数组，支持启用、停用和删除。
- 导入由现有本地前端读取文件内容后逐条调用后端，不上传到外部服务。
- LLM 只读取启用中的片段，并按评论或私信上下文做本地关键词相关性排序，限制返回数量和总字符数。

## 验收标准

- 6 个 Markdown 文件均为 UTF-8，内容完整且可由知识库页面批量导入。
- 文件标题和标签能让 LLM 区分服务说明、意向识别、FAQ、获客话术、自动回复和人工接管。
- 旧知识数据自动兼容并生成检索片段。
- 知识库页面可以组合使用关键字、状态、分类、标签和来源筛选，并支持排序和分页。
- 批量启停、批量删除和导出备份可用，危险操作有明确确认。
- 重复文件不会产生重复知识，导入报告能说明跳过原因。
- LLM 检索只引用启用知识，并返回与当前评论或私信相关的有限片段。
- 现有知识新增、编辑、启停和删除能力保持可用。
- 前端相关测试和全量测试通过，生产构建成功。
