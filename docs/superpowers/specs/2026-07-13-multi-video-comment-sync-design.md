# 多视频评论串行采集设计

## 目标

在线索私信页面支持两种外部视频来源：粘贴单个抖音分享链接，以及从历史搜索结果中多选视频。评论采集由后端持久化队列执行，严格串行、可观察、可恢复，避免短时间集中请求。

## 视频来源

### 分享链接

- 接受完整分享文案、`v.douyin.com` 短链接、抖音作品链接和数字作品 ID。
- 复用项目现有作品链接解析能力，解析成功后保存为当前账号的外部视频。
- 页面显示解析出的作品 ID；解析失败时返回可读错误，不创建采集任务。

### 搜索结果

- 用户选择一条历史搜索记录。
- 页面以分页列表展示该次搜索的视频。
- 支持逐项勾选、选择当前页、全选全部结果和反选。
- 创建任务时提交去重后的作品 ID 列表。

## 数量规则

- “评论数量”表示所有选中视频合计的目标评论数，不是每个视频的数量。
- 默认值为 200，允许范围为 1 至 5000。
- 队列累计保存的非重复评论达到目标后停止采集。
- 尚未处理的视频标记为跳过，原因是“已达到评论目标”。
- 如果所有视频都采集完成但评论总数不足，任务正常结束，并显示实际保存数量。

## 后端任务模型

- 新增批量任务类型 `comment-sync`，继续使用现有 `batch_jobs` 和 `batch_items`。
- 一个视频对应一个批量子项。
- 父任务输入保存目标评论数、分页大小、页间等待、视频间等待和重试参数。
- 父任务进度额外保存累计抓取、累计保存、重复数量、当前视频和当前分页。
- 任务必须使用单执行器，任何时刻最多处理一个视频的一页评论。

## 执行与限速

- 视频严格按选择顺序执行，不并发。
- 单个视频内部逐页调用原有评论 Bridge 接口。
- 页间默认等待 1.5 至 3 秒，视频间默认等待 4 至 8 秒。
- 可重试错误使用指数退避，默认最多重试 2 次，基础等待不少于 15 秒。
- 连续 3 个视频失败时自动暂停，避免持续触发请求。
- 支持现有批量任务的暂停、继续、取消和仅重试失败项。
- 应用重启后，运行中的任务恢复为暂停状态，由用户手动继续。

## 数据与去重

- 评论继续写入现有 `comments` 表，按评论 ID 去重。
- 视频继续写入现有 `videos` 表，不创建第二套视频数据。
- 每完成一个视频，立即从该视频评论同步 `dm_leads`。
- `dm_leads` 按“发送账号 + 目标用户 ID”唯一。同一个目标用户评论多个视频时只生成一条线索；不同发送账号允许分别联系该用户一次。
- 新增 `dm_lead_sources` 保存线索关联的全部来源评论。同一用户在 A、B 视频下的评论都保留，关键词搜索和 LLM 分析可以综合这些评论，但只生成一份私信草稿。
- 私信发送成功后，线索标记为“已联系”。后续采集到该用户的新评论只追加来源，不改变已联系状态，也不能创建第二个发送任务。
- 创建发送任务和实际调用 Bridge 前都检查“发送账号 + 目标用户 ID”的已联系状态，防止旧页面、重复勾选或恢复任务造成重复发送。

## API

- `POST /api/external-videos/resolve`：解析并保存单个分享链接。
- `POST /api/comment-sync-jobs`：根据账号、作品 ID 列表和评论总量创建任务。
- 任务运行、暂停、继续、取消、重试和查询继续复用现有批量任务 API。
- 批量任务响应提供评论累计进度，前端不接收大块原始评论 JSON。

## 页面交互

- 线索私信页面的视频来源使用“分享链接 / 搜索结果”分段切换。
- 分享链接模式显示一个粘贴框和“解析视频”命令。
- 搜索结果模式显示历史搜索选择框和可分页勾选的视频列表。
- 来源区域下方显示“已选择 N 个视频”和评论总量输入框。
- “开始采集评论”只创建并启动一个后端任务。
- 运行中显示确定进度条、当前视频、视频进度、评论进度及错误摘要。
- 线索行显示来源评论数量，并允许展开查看该用户在不同视频下的全部评论。
- 采集完成后自动刷新线索表；关键词、LLM、审核和私信发送流程不变。

## 错误处理

- 链接解析失败、作品无效、Bridge 离线、页面接口失败分别显示明确原因。
- 单个视频失败不会立即终止整个任务；退避重试后继续下一个视频。
- 任务被暂停、取消或应用退出时，已保存的评论和线索不回滚。
- 重试失败项时只重新处理失败视频，不重复创建已保存评论。

## 验收标准

1. 粘贴分享文案能够解析单个视频并采集评论。
2. 可以选择历史搜索结果并全选、反选多个视频。
3. 选中多个视频、目标 100 条时，后端始终只有一个评论请求在执行。
4. 页面持续显示视频与评论采集进度，不表现为卡死。
5. 累计达到目标后停止，并跳过剩余视频。
6. 暂停、继续、取消、仅重试失败项和重启恢复有效。
7. 评论落库后自动出现在去重后的线索列表。
8. 同一发送账号采集到同一用户在多个视频下的评论时只生成一条线索、一个草稿，并且最多发送一次；其他发送账号仍可独立联系一次。
9. 全量测试和桌面生产构建通过。
